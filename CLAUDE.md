# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Browser Pong "Edición Arcade" — a 100% static frontend app. Vanilla JS (classic scripts sharing the global scope), HTML5 Canvas, TailwindCSS via CDN. **No build step, no npm, no bundler, no linter.** Editor type checking is `jsconfig.json` + JSDoc; changes are verified in a real browser through Playwright MCP (see «Verifying changes»).

**Hard requirement: the game must work by opening `index.html` directly (`file://`) as well as on GitHub Pages.** That is why the code uses classic `<script>` tags and not ES modules (browsers refuse modules from `file://`). Don't introduce `import`/`export`, `type="module"`, `fetch()` of local files or anything else that needs a server.

Code, comments, UI strings and commit history are in **Spanish**. Keep new code and UI text in Spanish to match.

## Running

Open `index.html` in a browser — that's all the game needs. For development, serve the folder with `python tools/serve.py` (port 8000): it sends `Cache-Control: no-store`, otherwise the browser heuristically caches stale JS and you end up checking old code.

Deployed as a GitHub Pages static site — the repo root is the web root.

### Cache-busting is manual: one version N

`index.html` loads every file of `js/` with its own `<script src="js/…?v=N">` and the stylesheet as `css/style.css?v=N`, all with the same N. **After editing any JS or CSS, bump N everywhere**, or GitHub Pages (which caches ~10 min) serves stale files. **Adding, moving or deleting a file of `js/` means updating the script list.** Check it by hand: one tag per file of `js/`, all with the same `?v=N`, none `type="module"`, and `main.js` last.

## Architecture

### Layers

```
js/main.js      entry point: calls every init*() in order
js/core/        base layer — constants, storage, settings, state
js/data/        static catalogues — themes, lore, cutscenes/ (the prologue: PROLOGO and its generated PROLOGO_ASSETS; the floor arrivals: LLEGADAS; the ending, in final.js: LLEGADAS[5], FALSO_FINAL, CREADOR_INTRO, FINAL_VERDADERO, CREDITOS), campaign-art (CAMPAIGN_ART, generated), achievements, shop, levels, missions, power-ups, mechanics (MECH), music, news (Novedades)
js/systems/     audio (SFX), music (player), theme, input (keyboard), pointer (mouse + touch), stats, achievements, progression, missions
js/game/        canvas, draw, effects, balls, ai, mechanics, physics, match, hud, hints, loop, render, powerups, practice
js/vfx/         random (vfxRandom, vfxHash, the vfxNow/vfxT clock, and sfxRandom for audio), tint (campaign art images and their theme-tinted masks), shop cosmetics — trails, backgrounds, paddles, balls, goal-fx, super (smash styles) — and mechanics (MECH_FX) (+ index.js facade)
js/bosses/      index.js (table + dispatchers), shared.js, one file per boss, phases.js (fights by phases, lives, K.O., taunts)
js/campaign/    progress (boss in play, VS, advance, campaignBest), menu (Torre Hachepe + prologue), dialogue, finale
js/cutscene/    fx and fx-final (the scene effects), player (the scene player: playCutscene)
js/ui/          screens, howto («Cómo jugar»), news (Novedades), actions (data-action registry), settings-panel, stats-panel, shop-ui, shop-preview (the shop's animated preview), progress-display, progress-ui (rank emblem)
```

All files are classic scripts: their top-level `const`/`let`/`function` share one global scope, so **every top-level name must be unique across the project and must not collide with a `window` property** (grep before naming). Each file starts with `'use strict'`. Files call each other freely inside function bodies (those run after every script has loaded), but **top-level code may only use what `index.html` loaded before it**. The script list follows the layer order above; within it, the only cross-file top-level dependencies are:
- `core/state` uses `core/constants`; `core/settings` uses `core/storage`; `systems/audio` and `systems/music` read `settings` when they load;
- `bosses/index` builds `BOSS_MECHANICS` from the six boss files — so `shared` → bosses → `index` (then `phases`, which has no top-level dependency);
- `campaign/menu` builds `TOWER_ORDER` from `CAMPAIGN_CREATOR` (`data/lore`);
- `cutscene/player` builds `CUTSCENE_ASSET_SETS` from `PROLOGO_ASSETS` (`data/cutscenes/prologo-assets.js`, loaded right after `data/lore.js`, before `prologo.js`);
- `data/cutscenes/llegadas.js` uses `C_HP` from `prologo.js`, so it loads right after it, and `final.js` (which also writes `LLEGADAS[5]`) right after that;
- `cutscene/player` looks effects up in `CUTSCENE_FX` (`fx.js`) and `CUTSCENE_FX_FINAL` (`fx-final.js`), at call time.

Breaking the order throws a `ReferenceError` at load and every test fails.

### Shared state

- Mutable match state read by several files lives in the `state` object (`js/core/state.js`, typed `GameState`): `mode`, `isPlaying`, `isPaused`, `p1Score`, `p2Score`, `frameCount`, `serveCountdownMs`, shake, `hitStopMs`, `fever`/`feverHeat`, `balls`, `particles`. **Anything another file must write goes in `state`** (e.g. the campaign sets `state.isPlaying = false`). The paddles `p1`, `p2` and `p2Twin` are stable objects declared next to it; besides their box they carry the mechanics fields (`vy`/`vx` and `prevY`/`prevX`, `charge`, `smashHeld`, `smashTouchHeld`, `releaseMs`, `energy`, `superArmed`), reset by `resetPaddleMechanics()` in `startGame()`. Paddles have no `dy`/`dx` any more. `p2` and `p2Twin` (Valen, only in the duo fight, at `p2`'s x) also have `retreatMs`: while it runs the paddle is neither clamped nor hit by the ball (`clampPaddles`, `hitPaddles`); `startGame()` zeroes both. Balls carry `spin`, `power` (`null`/`'smash'`/`'super'`), `owner`, `squash` (visual) and, in the duo fight, `hitter` (`'mario'`/`'valen'`).
- Other top-level `let`s (`currentCampaignLevel`, `isDialogueActive`, `activePowerup`, `bossState`…) are reassigned only by the file that declares them; other files only read them. Keep it that way, or add a setter.
- `state.balls` is replaced wholesale by `resetBall()`, even mid-`update()`: **never keep a reference to the array across calls**; read `state.balls`.

### Boot and events

- No file registers listeners or touches the DOM while loading (reading `localStorage` and looking up the canvas are the only load-time work; music `Audio` elements are created the first time a track plays). `js/main.js` calls `initAudio`, `initInput`, `initCanvas`, `initPointer`, `initTowerControls`, `initCutscene`, `initActions`, `refreshMissions`, `initUI`, `initNews`, `syncExclusives` in that order (`initNews` opens Novedades on top of the main menu when `settings.seenNewsVersion !== NEWS_VERSION` or `settings.progressWasReset`; `syncExclusives` hands over the exclusives whose condition was already met, with their toast). **Keep `initAudio` before `initInput`**: both listen to `keydown` on `window`, and same-target listeners run in registration order.
- The markup has **no inline handlers**. Controls declare `data-action="fn"` (click), `data-input="fn"` or `data-change="fn"`, plus `data-arg` when the call takes an argument. `js/ui/actions.js` has one registry per event type, named after the functions they call, and three delegated listeners on `document`. Adding a control = adding a registry entry that **converts its argument** (dataset values are strings: `towerSelect("1")` would compare a string to a level number). Unknown actions throw.
- Every menu is a `<section class="screen">`; `showScreen(id)` (`js/ui/screens.js`) shows one. «Cómo jugar» (`#howto-menu`, `js/ui/howto.js`) opens from the main menu, the pause or Novedades and its back button returns there; opened from the pause it toggles the classes itself (like `togglePause`), so the match stays paused with its music ducked, and ESC closes it back to the pause. Its key labels come from `settings.bindings` each time it opens. Outside a match (`!state.isPlaying`), every screen except the ones layered on the field (`MATCH_OVERLAY_SCREENS`: pause, game over, VS) hides `#game-container`, and `main-menu` always does; `quitGame()` also hides it and clears `body[data-game-mode]` and `data-smash` itself, because practice returns to «Cómo jugar» or mode select, not the main menu. `shop-menu`, `campaign-menu` and `progress-menu` re-render; every screen sets its music through `screenMusic(id)` (see `systems/music.js` below). Novedades (`#news-screen`, `js/ui/news.js`) is not a screen of its own either: `openNews()` keeps `main-menu` active (and `inert`) underneath — full screen below 900 px, a 760 px dialog above. It opens by itself on the first load of a version (or after a progress reset) and from `#news-btn` (with a dot while unseen); closing it (¡A JUGAR!, ✕ or ESC) stores `seenNewsVersion` and clears `settings.progressWasReset`. Its reset notice shows only while `settings.progressWasReset` is set (by the phase 4 reset, see Persistence). Gameplay is not a screen — `startGame(mode)` hides all and shows `#game-container`; pause and game-over are screens layered on top. `#cutscene-screen` is a screen that `playCutscene()` activates itself (see Cutscenes).

### Game loop (`js/game/`)

`loop.js` runs `update(dt)` (`physics.js`) then `render()` (`render.js`) per `requestAnimationFrame`. `dt` is normalized to 60 FPS units (`elapsedMs / MS_PER_FRAME`, clamped to ≤3), so speeds are "pixels per frame at 60 FPS" and every movement is multiplied by `dt`; `dt * MS_PER_FRAME` converts to milliseconds. `render()` layers are listed in its header (the boss's floor, `bossRenderArena`, right after the background and before the glow and the net; fever after it, smash aura before each ball, spin right after it, smash charge after the paddles, `MECH_FX.render` after the particles).

`update()` is a fixed sequence of named steps: dialogue pause → hit-stop (only counts `state.hitStopMs` down and returns; `render()` keeps drawing the frozen frame) → phase hold (`bossPhaseHold()`: while a fight by phases is in its transition or K.O. only particles and shake advance; it does nothing in any other fight or mode) → slow-motion → boss update → remember paddle positions → player 1 → player 2 or CPU (`ai.js`) → clamp (a paddle that hits the edge loses its speed) → measure pointer/CPU paddle speeds → smash charge of the human paddles → serve countdown → match clock and match-point music (`tickMatchPointMusic`, sound only) → balls (move, spin, squash, walls, boss obstacles, paddles, the practice wall, goals) → power-ups → fever heat → VFX → particles → shake. **The order is behaviour**: physics, the screen shake and the bosses share `Math.random`, so reordering changes every later random number. **Visual effects use `vfxRandom()` (`vfx/random.js`), never `Math.random`**, so a cosmetic never changes a match; **audio uses `sfxRandom()`, neither of the other two**, so a sound never changes the match or what the cosmetics draw. Renderers read the time from `vfxNow()`/`vfxT()` (`vfx/random.js`), a clock that `updateVFX(fxDt)` advances, **never `performance.now()` or `Date.now()`**: cosmetics freeze in the pause, the hit-stop and dialogues, and slow down with slow-motion. `measureFxLoad()` (`game/loop.js`) sets `state.lowFx` when the match stays under 45 fps for 3 s (until `startGame()` clears it); the heaviest cosmetics (galaxy, glitch) then draw half their particles. It only changes drawing. `prefersReducedMotion()` (`game/effects.js`) only draws less (no shake offset, half the particles, lighter goal effects): **it must never change how many times `Math.random` is called** — the shake still draws its two numbers. Two early exits are explicit return values: during the serve countdown only the VFX, the particles and the shake advance (in that order, as at the end of the frame), so the goal shake ends on time instead of lasting the whole countdown; and a match-ending goal with several balls stops the frame, while with one ball the rest of the frame still runs (`onBallOut` in `physics.js` documents the asymmetry).

- Fixed logical resolution `GAME_WIDTH × GAME_HEIGHT` = 800×600. `canvas.width/height` are always the logical size; `resizeCanvas()` only sets CSS size: it picks the HUD layout (`#game-container[data-layout]`: `top` on desktop/tablet, `sides` in short landscape, `stack` in portrait) and fits 4:3 into the real size of the `#canvas-wrapper` grid cell.
- Slow-motion is a `dt` multiplier. The power-up's (`getSlowmoMultiplier()`) slows the match; the epic goal's (`getGoalSlowmo()`, a cosmetic) only slows what is drawn: `fxDt` feeds `updateVFX` and `updateParticles`, never the paddles, the serve countdown or the shake (which draws from `Math.random`). `realDt` is the `dt` before both: the match clock and the slow-motion power-up itself (10 real seconds) count with it.
- `update()` returns at once while `isDialogueActive` — that is the campaign's "pause".
- `checkWin()` (`match.js`) is explicit orchestration, not events: sound (the track fades out and the jingle plays, `playMatchEndSound`) → dialogue → campaign victory → stats → achievement → rewards → displays → paddle restore → music (narrated endings only) → narrative sequence. That order is behaviour too.

### Game modes

`state.mode` (`GameMode`) is set by `startGame(mode)`: `'cpu'` | `'local'` | `'hachepe'` | `'campaign'` | `'practice'`.

- `cpu` — AI paddle speed/dead zone from `settings.difficulty` (1/2/3), plus the mechanics plan below.
- `local` — both paddles human; **awards XP but no Chemi Coins** (anti-farming, `awardGameRewards` in `systems/progression.js`).
- `hachepe` — standalone boss mode: fast near-perfect AI, exclusive music, target score 10. Deliberately separate from the campaign.
- `campaign` — see below.
- `practice` (`game/practice.js`, entered with `startPractice(from)` from «Cómo jugar» or mode select) — the player against a wall (`PRACTICE_WALL`) covering the right edge: no CPU (`moveCpu` is skipped and `hitPaddles` ignores `p2`), no power-ups, no rewards, stats or achievements (`statsCountMatch()` keeps the play clock and the totals still; `checkWin()` returns `false` at once). The wall bounce (`bouncePracticeWall`) adds `±1.5` to `dy` with `Math.random` — the only new random call, and only in this mode — and drops a smash to the normal top speed. A miss (`practiceMiss`) counts in `state.p2Score`, resets the rally and serves again. Every mechanic works, fever music included. The HUD shows the best rally (`matchBestRally`) in the player's card and the misses in the «PARED» card; «SALIR» in the pause returns to `practiceReturnScreen`.

### Hit mechanics (`data/mechanics.js`, `game/mechanics.js`)

Every number lives in `MECH`; never repeat one as a literal. `game/mechanics.js` keeps `physics.js` a list of steps.

**Naming: in the code, `super` is the player's smash.** There is one special hit, the smash, and it needs a full energy bar. The identifiers kept the old name (`HitType 'super'`, `b.power === 'super'`, `superReadyFor`, `SUPER_FX`, `superStyleId`, the shop category `'super'`, `equipped.super`, `super_*.svg`, `#super-hint`); everything the player reads says «Smash». The old free smash (no energy) no longer exists.


- **Kinematics.** Keyboard paddles have inertia (`movePaddleKeys`: accelerate with `accelK`, brake with `decelK`; charging a smash slows them by `smashSlowK`). Finger and mouse still jump to the pointer (`followPointer`, capped while charging) and their speed is *measured*, like the CPU's and the twin's (`measurePaddleSpeeds`). `vNorm(p)` is the speed over `paddleSpeed`, −1…1; the rotated arena uses `x`/`vx`.
- **Hit model.** `hitPaddles()` only detects the collision; `resolveHit(b, paddle, maxBallSpeed, rotated)` classifies the hit by priority — `'super'`, the smash (the Rayo's `boltReady`; smash window open, `charge ≥ superMinCharge` and energy full or `superArmed`; or `smashTouch === 'auto'` with full energy and a finger on screen), perfect (`|c| ≤ centerZone`), edge (`|c| ≥ edgeZone`), block (paddle still), normal — and sets angle, speed (edge and block never go below the serve speed; a rival smash is capped at the normal top first), spin, owner/power, energy, the smash reset, feel (sound, sparks, shake, hit-stop, haptics, squash), the VFX, `bossRefreshAim`, `setLastHitter`, the stats and the fever. `applySpin()` curves the ball in flight; walls multiply spin by `spinWallK`.
- **Smash.** `updateSmash(p, held, dt)` after moving each human paddle (and from `cpuPlay`): it only charges with `superReadyFor(p) || p.boltReady` — without a full bar, holding does nothing (no charge, no slowdown, no sound), and if the bar stops being full mid-charge the charge is cut without a window. Holding charges over `smashChargeMs`; releasing opens a `smashWindowMs` window; a hit while still holding is normal and loses the charge. The smash flies with `superSpeedK`/`superCapK`/`superAngleK`, the `super` hit-stop, shake and vibration, the equipped `SUPER_FX` style, sounds `superHit` and empties the energy. `goalPower(b)` is 0 or 2 (1 was the old free smash). `held` is `isActionPressed('p1Smash'|'p2Smash') || p.smashTouchHeld`. `releaseSmashCharges()` cuts the charge sound on pause, quit and match end.
- **Energy.** 0–100 per paddle (the twin's goes to `p2`): +6 per hit (normal, edge, block), +15 perfect, ×`feverK` in a fever, +10 to both every 10 rally hits; a smash empties it. Filling it plays `superReady` and, for player 1, shows `#super-hint`. Energy survives goals; `resetBall()` only closes charge and window.
- **Fever.** At `feverRally` hits `startFever()`: top speed ×`feverMaxSpeedK`, energy ×2, `fiebre_rally` music in VS CPU, local and practice only (`state.matchTrack` resumes in `endFever()`, called on any goal; at `MUSIC_DYNAMIC.feverBoostRally` hits the fever track goes up 2 dB). `state.feverHeat` is visual: `MECH_FX.fever` draws the gradient, flame tongues across the whole width and rising embers (`vfxHash` + `vfxT()`), and the flames grow 30 % from `feverBoostRally` hits. With reduced motion the flames are still drawn, frozen (no `t`), and the embers are skipped — Windows reports reduced motion when «Efectos de animación» is off.
- **CPU.** Only in VS CPU and Hachepe (`cpuPlay` in `ai.js`): when a ball starts coming it rolls a plan (always three `Math.random` calls: spin, `useSmash`, aim offset) from `MECH.cpu`, predicts the arrival point simulating bounces and (weighted) spin, aims the paddle centre at it, moves away from the player in the last frames for spin, and, only with its bar full and `useSmash`, holds/releases the smash with `updateSmash`. **Campaign bosses use the mechanics only if their config (or phase config) has `spin`/`smash`** (Chemi, Dani, the duo, Fano): then `bossPlay` (`ai.js`, `p2` with the slot `bossPlanP2`) rolls a plan per incoming ball (always two `Math.random` calls: spin, smash), chases `ball.y + bossAim()`, sweeps in the last frames for spin and holds/releases the smash with a full bar; `resolveHit` classifies their hits but turns a `block` into `normal`. `bossPlayPaddle(p, ball, aiSpeed, err, cfg, dt, slot, { goal, home })` is the same for any paddle with its own `BossPlanSlot` (`{ plan, wasComing }`), another target or another waiting height. A boss with an `ai` hook (the duo, Fano) moves its paddles itself: `moveCpu` calls `bossMoveAi(...)` before anything else. The others keep their AI and every hit is a plain normal one, without spin or block — a waiting boss would otherwise block every ball, slow it down and never miss. The player keeps every mechanic against all of them. The campaign has its own difficulty: `settings.difficulty` never reaches a boss and `currentSpeedPreset()` is always `BALL_SPEED_PRESETS[2]` there.
- **Touch.** `settings.smashTouch` and `settings.haptics` are set in Configuración › Partida (the haptics row only shows where `navigator.vibrate` exists). `#smash-btn-p1`/`-p2` exist only with `isTouchDevice()` and `settings.smashTouch === 'button'` (`data-smash` on `#game-container`, set by `setupHud()` before the field is measured; `"2"` in local). `'finger'`: a second finger in the player's half holds the smash (`activeTouches` stores it as `'p1Smash'`). `'auto'`: no charging, full energy makes the next finger hit a smash. The buttons are off without a full bar (`aria-disabled`, opacity 0.4, the ring shows the energy) and pressing them does nothing; full, they turn yellow with a soft pulse (none with reduced motion) and the ring shows the charge (`updateSmashButtons`). `isFingerOn(side)` (not `touchY`, which the mouse also writes) decides haptics and auto.

### Campaign: `campaign/` narrates, `bosses/` fights

`data/lore.js` holds the six Hachepes' story and dialogues; `campaign/` the flow; `bosses/` every fight mechanic. Each boss file declares a `BossMechanics` object (`{ config, init, update, render, renderOverlay, collide, onGoal, hidesBall, invertsControls, rotated, passesPaddle, drawPaddle, phases, lives, color, renderArena, onHit, koLeadMs, koTick, ai, ballAlpha, trailStyle, paddleColor, music, companions, onLine, paddleHidden }`, all optional but `config`). `onGoal(scorerIsP1, b)` gets the ball that went in and runs before the phase count; `onHit(b, side, type, paddle)` gets the paddle that hit (`p2` or the twin); `koTick(ms)` runs every step of its `koLeadMs`; `ai(target, aiSpeed, errorMargin, cfg, dt)` replaces the boss AI; `ballAlpha(b)` returns `{ ball, trail }` opacities (`render.js` draws that ball and trail in an offscreen layer, `drawDimmed`, because the cosmetics set their own `globalAlpha`); `trailStyle(b)` returns `{ tint }` (a plain coloured trail, `drawTrailTint`) or `{ id }` (another trail renderer); `paddleColor(p)` colours `p2`/the twin; `rotated()` turns on the rotated arena (your paddle horizontal at the bottom, the boss's at the top); `passesPaddle(b, p)` lets a ball through a paddle; `drawPaddle(ctx, p)` draws a paddle itself and returns `true`; `paddleHidden(p)` skips one; `music` is the boss's own track (default `jefe_hachepe`); `companions` (`{ id, color, cls? }`) are the busts in `.boss-side` next to its score; `onLine(line)` runs for every dialogue line or taunt shown. `game/` never names a boss: it calls the dispatchers in `bosses/index.js` (`bossRenderArena`, `bossOnHit(b, side, type, paddle)` after every hit, `bossOnGoal(scorerIsP1, b)`, `bossMoveAi`, `bossBallAlpha`, `bossTrailStyle`, `bossPaddleColor`…) and reads `bossConfig()` (`targetScore`, `aiSpeed`, `aiError`, `aiBias`, `spin`, `smash`, `maxBalls` — a cap on balls in play that multi-ball respects; with phases, the current phase's `config` on top). **Add a boss by adding a file and a table entry, never a `currentCampaignLevel === N` branch in `game/`.**

Two non-obvious rules learned from bugs:

- **`aiBias` is what makes a boss beatable.** `aiError` is a dead zone, and any dead zone smaller than the paddle's half-height (50px) never produces a miss. `aiBias` offsets the boss's *aim*, refreshed on every hit.
- **Obstacles belong on the boss's half, and must perturb `dy`.** A block on the player's half traps the ball in a paddle↔block loop; a block on the vertical centre intercepts every flat return. Chemi's turnstiles sit at x 580 and leave the centre lane (y 212–388) free; every bounce (arms, shutters) perturbs `dy` and `bossNormalizeBall(b, minX = 0.42)` (`bosses/shared.js`) never leaves the ball near-vertical. A bounce that goes straight back to the player (Dani's cells and vault door) uses `minX` 0.7 and half the perturbation: with Chemi's values not even a perfect bot reached them. `bosses/shared.js` also has `bossSign` (the small neon signs) and `bossSfx(name)` (plays a `soundEffects` entry if it exists).

`data/lore.js`: each Hachepe has `floor` (`'PB'`, `'1'`…`'4'`, the Creator `'S'`), `room`, `bust` (and `bust2` for the duo; keys of `CAMPAIGN_ART.bustos`), `title` (its alias: The Black, Grow Partner…), `image` (`assets/campaign/bustos/<id>.webp`), `desc` and `dialogues` (`start`, `phase2`/`phase3`, `win`, `lose`, `taunts`, Chemi's `creatorHint`). A line is a string (the boss speaks, or its speaker `a`) or `{ t, s, sfx, bust }`: `s` is `'a'`/`'b'` (bosses with `speakers`), `'player'` (the Unknown: «¿¿??», his bust with the theme mask in `#dialogue-avatar-player`, a canvas) or `'hint'` (no name, the bust flashes white/#E0F2FE for a frame); `sfx` plays `soundEffects[sfx]` when the line shows; `bust` swaps the bust for that line only (Chayipiti's `chayipiti_error`). **`speakers`** (the duo: `a` Mario, `b` Valen with `paddle: 'twin'`; Fano: `a` Fano, `b` Chayipiti with `voice: 'radio'`) is `{ a, b }` of `{ name, bust, color, voice?, paddle? }`, resolved by `dialogueSpeaker(lore, line)` (`campaign/dialogue.js`): the dialogue box (`.has-speaker`) takes the speaker's name, bust and colour (`--c`/`--c-a`), and `voice: 'radio'` adds `.is-radio` (jittering text, frozen with reduced motion) and higher blips (`dialogueBlip({ radio: true })`); `voice: 'glitch'` (the Creator) adds `.dialogue-glitch`: the text shakes and some letters flip to glitch characters for a moment. Yisus has a third speaker `c` (Pedro), the Creator `b` (Pedro) and `n` (the boy). Taunts accept `{ t, s }` too: `#boss-bubble.has-speaker` sits next to the speaker's paddle (`--bubble-y`, refreshed in `updateBossBubble`; `paddle: 'twin'` → `p2Twin`), with the speaker's colour, and a `voice: 'radio'` line carries the speaker's small face (`#boss-bubble-face`). `image`/`image2` are only for the tower and the VS screen. The busts are square head-and-shoulders: framed in the VS screen, square in the dialogue and the HUD badge, a circle on the game-over screen.

Flow: the first time the campaign opens, `renderCampaignMap()` plays the prologue (see Cutscenes; VER HISTORIA replays it). It builds the **Torre Hachepe** → `campaignEnterFloor(level)` → `prepareCampaignMatch(level, opts)` → VS screen → `startCampaignGame()` → `startGame('campaign')` + `queueDialogue()`. **Arrival scenes** (`LLEGADAS`, `data/cutscenes/llegadas.js`: 2 = Dani, 3 = the duo, 4 = Fano; `final.js`: 5 = Yisus, with `keepMusic`; all on the shared `PROLOGO_ASSETS`): `campaignEnterFloor` (from the end of the elevator ride and from SIGUIENTE HACHEPE, `nextCampaignLevel`) plays the floor's arrival when `playerProgression.campaignArrivals[level]` isn't set; its `onEnd` (also on skip) marks it, saves and goes on to `prepareCampaignMatch`. ### Cutscenes (`cutscene/`, `data/cutscenes/`)

The campaign prologue is a ~4:50 film (17 scenes, with auto-advance at normal text speed) played by a data-driven scene player. The full spec is `design/campana/prologo/guia-implementacion.md` plus the extension in `design/campana/rework-torre/guia-implementacion.md` (scenes 3–12 and 17); the script and art direction are the owner's docs they link. Nothing of the Creator appears in it. The ending's films use the same player (`design/campana/final/guia-implementacion.md`, with `pantallas/maqueta.html` for the look).

- **Data.** `PROLOGO` (`data/cutscenes/prologo.js`, 17 scenes, the approved dialogue, copied from `design/campana/rework-torre/datos/`) and the three arrivals in `LLEGADAS` (`data/cutscenes/llegadas.js`, one scene each, copied from `design/campana/pisos-1-3/datos/`; no `endCard`) are `Cutscene`s (`{ id, assets, endCard, noSkipFirstTime, keepMusic, scenes: [{ id, steps }] }`; `keepMusic` leaves the music playing when the film is skipped; typedefs `Cutscene`/`CutsceneScene`/`CutsceneStep`/`CutsceneAssets` at the top of `cutscene/player.js`). `assets: 'PROLOGO_ASSETS'` names the manifest by its global name; `player.js` maps it in `CUTSCENE_ASSET_SETS`. **`data/cutscenes/prologo-assets.js` and `data/campaign-art.js` are generated** by `design/campana/generadores/` (`build_prologo.py`, `build5.py`, `build6.py`, `merge5.py`; Python + Playwright, dev machine only; its `README.md` explains them) together with the WebP files in `assets/campaign/` (`prologo/fondos/`, `prologo/actores/`, `bustos/`, `torre/`, `chemi/`, `pisos/`): never edit them by hand, rerun the generators. Each image is `{ src, w, h, ax, ay, theme }`; in `PROLOGO_ASSETS` in scene units (960×540, images at 2 px per unit; `ax`/`ay` are the feet; the `busto_*` actors are the shared busts), in `CAMPAIGN_ART` busts at 4 px per unit and tower/arena at 2. `theme` is a white-with-alpha mask tinted with the theme colour.
- **API.** `playCutscene(def, { onEnd })` (activates `#cutscene-screen` by toggling the classes itself, not through `showScreen`, and stops the music), `stopCutscene()` (no `onEnd`; skipping a film with no `chapter` step and no `endCard` calls `onEnd` at once, with no chapter card), `cutscenePlaying()`, `cutsceneProgress()` (`{ phase, scene, id, t }`, read-only, for Playwright). `showScreen()` leaves the music alone while a cutscene plays, because `renderCampaignMap()` starts the prologue from inside `showScreen('campaign-menu')`. Campaign: `playCampaignPrologue()` (`campaign/menu.js`) plays `PROLOGO` the first time the campaign opens (`!campaignIntroSeen`) and from VER HISTORIA; its `onEnd` (also on skip) sets `campaignIntroSeen`, saves and returns to `campaign-menu`, which brings back `musica_menu`.
- **Steps** run in order; `say`, `narrate`, `card` and `wait` block, every other step starts at once (or after its `delay`). `bg` (cross-fade; `id: 'negro'` is solid black, on purpose not in the manifest), `camera` (`x, y, zoom`, optional `dur`/`ease`), `actor` (creates or updates; given `x`/`y` cut that actor's running moves), `move`, `fade`, `pose` (0.1 s white flash), `remove`, `clear` (`keep: ['rain']` keeps the rain effect and the `rain` loop), `say` (`who` — an actor id, or a name with no actor such as `'radio'`/`'ventana'`: no camera focus —, `name`, `color` or `'theme'`, `portrait` — an id that already is a `busto_*`, or the `busto_<id>` bust when the manifest has it, drawn whole; else the top of the sprite —, `radio`, `auto`), `narrate` (`auto` = max seconds), `card` (freezes the scene clock, dims everything but its actor, plays `sfx` and `after` 0.6 s later, 3 s or until advanced; it stores `color` on the actor, which `balls` uses), `wait`, `fx`, `music` (`musicPlay(track, { fade, from })` / `stop: true`; unknown tracks are skipped), `sfx` (`soundEffects[name]`; a function returned is a loop, stopped on skip, end, `clear` or `stop: true`). A step that throws is logged and skipped: the film never hangs.
- **Steps of the ending.** `bg: 'blanco'` (`#F8FAFC`, like `negro`); `elevator_open` with `count` (the LED walks through the values, inside `dur`); `move` with `rot` (degrees); `say` with `style: 'creator'` (`.is-creator`, no name or portrait, console font, shaking border; in the `tall` layout, over the fake menu, it goes on top), `glitch: true` (`.is-glitch` on the portrait) and tokens in the text: `{partidas}`, `{monedas}` (thousands dot), `{nivel}`, `{dispositivo}` («el teléfono en la mano» with `(pointer: coarse)`, else «la mano en el ratón»), filled when the line shows (`cutsceneFillTokens`) and wrapped in `.cs-token`.
- **Clocks.** `cs.t` is the scene clock (seconds): moves, waits and effects run on it; it stops during a card and slows with `fx: slowmo` (whose `dur` is real time). Typing, auto-advance, cards and skip-hold use real time (`cs.realT`). The loop is its own `requestAnimationFrame`, stopped when the cutscene ends.
- **Drawing.** Camera transform `translate(view centre) · scale(k · zoom) · translate(-x, -y)`, clamped so the view never leaves the 960×540 scene, plus shake. Actors are drawn by `y`, flipped about their `x`, with frames at `fps` (0 = first frame), a 1.5-unit step bob while moving (`bob` overrides it) and a 1 ± 0.008 breath when still. Layers: background (and the previous one while it fades) → `'bg'` effects (wipe, streak, headlight beams) → actors → `'world'` effects → `'screen'` effects (view units, no camera: rain, flash, veil, lightning, glitch) → the card's dim and actor. Tinting lives in `vfx/tint.js`, shared by the prologue, the tower and Chemi's arena: `artLoad(src)`/`artImage(src)` (one `new Image()` per src), `tintedMask(src, colour)` (an offscreen canvas, `fillRect` the colour, `'destination-in'` the mask; cached per `src|colour`, cleared when the theme changes or a cutscene ends) and `drawTintedArt(ctx, info, colour, x, y, w, h)` (the image plus its mask with `'lighter'`). The match effect asks the camera to see 700 units of width in `tall` (`cs.fitW`). **Never use `getImageData` (or anything that reads canvas pixels) in cutscenes: on `file://` the canvas is tainted by local images and it throws.** Images load with `new Image()`, never `fetch`; a failed image warns once and the scene goes on without it. Scenes 1–3 load behind a thin theme-coloured bar (10 s cap), and each scene preloads the next.
- **Effects** (`cutscene/fx.js`, `CUTSCENE_FX[type](step, cs) → CutsceneFx | null`, state in the factory's closure): `crt_on`/`crt_off`/`title`/`chapter` in the DOM, and `elevator_open` (`floor`, `dur`: screen layer, two steel doors with a gold frame cover the view from the first frame and, after 0.3 s with the floor on the LED, slide apart in `dur`; a fade with reduced motion), `traffic`, `spark`, `shake`, `dust`, `beams`, `flash`, `veil`, `balls` (`to: 'left'|'right'` or a point `[x, y]` where they vanish), `glass`, `explosion` (flash, 0→90 ring in 0.4 s, 24 sparks), `leaves`, `knockout` (CSS `blur()` on `#cutscene-canvas` 0→5 px, a red vignette beating every 0.9 s, black in the last second; the black stays until the next `bg` or `clear`, which remove it and its filter), `versus` (screen layer: two `busto_*` busts sliding in, names, a diagonal band with `text`/`sub`), `match` (the Yisus vs mayor game on `cancha`: court 150,96–810,486, paddles at x 170/790, rallies of 3–5 hits with `vfxRandom`, `paddleHit` per hit; a `match_hud` companion draws the score and the corner busts — the mayor shakes and sweats, Yisus glows; `smash: true` charges an aura, fires a big ball and breaks the right paddle in two), `glitch` (canvas copied onto itself in bands, RGB split through an aux canvas), `calendar`, `wipe`, `rain` (one per film: another `rain` step changes `density` or turns it off), `lightning`, `slowmo`, `streak`, `eyes`, `scarf_gust`. Randomness only from `vfxRandom()`/`vfxHash()`. Reduced motion (`prefersReducedMotion()`, read when the film starts): no shake, flash, lightning or glitch, no title/spark flicker, one `streak` copy, and background cuts become 0.3 s fades.
- **Effects of the ending** (`cutscene/fx-final.js`, `CUTSCENE_FX_FINAL`, same contract; mostly DOM with the classes under «El final de la campaña» in `style.css`, marked `.cs-dom-fx` so the player removes them; text with `textContent`, never `innerHTML`). `CUTSCENE_BLOCKING_FX` block the film: `console` (`lines`, `cps`, `hold`, `clear`, `center`, `dark`), `error_window` (the fake system window, generic and grey: `.sys-window`; both buttons lead to the same place), `name_box`, `credits` in `verdadero` mode. The rest: `fake_menu` (`dur`/`off`: the real `#main-menu` with `.is-fake-menu` above the canvas, a button turns to «NO» every 1.5 s; touching one only shakes it; `off` restores every text and class), `bust_glitch` (`bust`, `rays`, `dur`/`off`), `reveal` (`text`, `image`, `imageMs`; reduced motion: only the image with a fade), `crack`, `hearts`, `big_text`, `flicker`, `wipe` with `mode: 'shutters'`, and `credits` (`mode`, `lines` — `'CREDITOS'` reads the global —, `breakAt`, `corrupt`; `verdadero` runs ~110 s with the `wink` glitch on Chemi's bust).
- **Layout** (`cutsceneLayout()` on start and resize, `data-layout` on the section, the scene rectangle in `--cs-x/-y/-w/-h`): `wide` — the whole scene (`contain`), dialogue at the top over the sky, SALTAR bottom right; `band` — landscape with side bands ≥ 64 px, SALTAR round in the right band; `tall` (height > width) — the canvas full width and `min(100vw, 52vh)` high with `cover`, dialogue, SALTAR and SIGUIENTE below; there the camera x eases to whoever speaks (`who`) or has the card (`cutsceneTickFocus`). Canvas at `devicePixelRatio` capped at 2. Narration: two 12 % cinema bars and large text on the bottom one.
- **Controls.** Tap/click anywhere (`data-action="cutsceneAdvance"` on the section), SPACE or ENTER complete the line or advance; SALTAR (`cutsceneSkip`), ESC, or holding SPACE or a finger 1 s (the SVG ring fills; pointer hold registered by `initCutscene()`) skip to the `chapter` card for 1.5 s and then `onEnd`. While a cutscene plays `handleKeyDown` hands every key to `cutsceneKey()` and nothing reaches the game. Lines auto-advance `2 s + 50 ms × letters` after they finish, scaled by the text speed; while text is on screen the music dips 3 dB (`musicDuckWhile`).
- **Text speed.** `settings.textSpeed` (`'slow'`/`'normal'`/`'fast'`, «Velocidad del texto» in Configuración › Partida, `updateTextSpeed`): 20/35/60 letters per second and auto-advance ×1.3/×1/×0.75 (`CUTSCENE_TEXT_SPEEDS`). Only cutscenes use it.

### Cosmetics: shop → progression → vfx

`SHOP_CATALOG` (`data/shop.js`) has 7 categories `trails`/`backgrounds`/`paddles`/`goalEffects`/`balls`/`super`/`music` (`music` is the Rockola: see below); `SHOP_CATEGORIES` lists the tabs. Everything for sale costs **7 620 coins** (about level 35–40): recompute that figure here if a price changes. Buying calls `purchaseItem(cat, id, cost)`, equipping `selectCosmetic(cat, id)` (`cat` is the `SHOP_CATALOG` key), which writes `playerProgression.equipped[cat]`. The `vfx/` renderers read `equippedId(cat)` **every frame** through their id → renderer tables. Adding a cosmetic = a renderer in the right `vfx/` table + a catalogue entry with the same `id` + an SVG icon in `assets/shop/` (`<prefix><id>.svg`; if it uses `var(--primary)`, also inline it in `SHOP_ICONS`, because an `<img>` doesn't inherit CSS variables). Rarity is derived from the price (`shopRarity(item)`: 0 inicial, <100 raro, <300 épico, else legendario), not stored. **Exclusives** (`trails:glitch`, `backgrounds:hachepe_walls`, `paddles:gold`, `paddles:pedro`, `goalEffects:crown`) have `price: 0` plus `exclusive: { label, check }` and are never sold: use `shopIsFree(item)` (not `price === 0`) for "everyone owns it", and keep them out of the Fashionista count. `grantExclusive(key)` (idempotent: sound, «¡Objeto exclusivo!» toast in the achievement queue, `exclusive_first`) is called by `syncExclusives()` on load and after every `unlockAchievement`, and by `checkLevelUp()` at level 50. The locks of Glitch and Pedro's paddle (`exclusive.secret`) read «Logro secreto» until the campaign reveals the Creator (`shopLockLabel`). Balls go through `renderBallVFX()` (`vfx/balls.js`), which applies the hit squash to every style; a boss that hides or dims the ball (any boss in its K.O., Fano's dark stripes) still wins. The smash style (category `super`) is the one equipped by whoever threw it (`superStyleId(owner)`: player 1, or player 2 in local); the CPU, Hachepe and bosses always use `energy`. **Shop v2** (`ui/shop-ui.js`): the daily offer, the tab row, the «Estelas · 3 de 11» line with the sort select, and one `<article>` per item with two real buttons — the icon tile (`previewShopItem`) and the action (`buyShopItem`/`equipShopItem`, or disabled EQUIPADO / exclusive lock), all `data-action` with `data-arg="cat:id"`. A buy button the coins don't reach is dimmed but clickable: `shopDenied()` shakes the wallet and plays `soundEffects.denied()`. The **daily offer** (`shopDailyOffer(date)`) is the first unowned paid item of a shuffle seeded with `missionHash('oferta:' + day)` (`missionRng`, never `Math.random`), at −30 % rounded to 5; buying it stores `dailyOfferBought` and hides the card until the next local midnight; buying anything else doesn't change it. `buyShopItem` charges the offer price, equips, and unlocks `buy_legendary`/`fashionista` (`grow_partner` comes from `purchaseItem`). The **animated preview** (`ui/shop-preview.js`) is one 400×300 canvas that runs only while the shop is visible: in the side panel at ≥1200 px, or inside the tapped card's tile below that. It draws with the real `vfx/` renderers, advances `vfxTick`, and on stop resets what it shares with the match (`resetGoalVFX`, `clearSuperBursts`, the equipped background). Goal effects are `GOAL_FX[id] = { trigger(x, y, color, power), update, render, reset }`: `power` is `goalPower(b)` (0 normal, 1 smash, 2 super) and `resetGoalVFX()` calls every `reset()` — on start, quit and when another goal effect is equipped. Backgrounds are the only stateful ones (`init()`, `update(dt, ball)` — `ball` is `state.balls[0]` or `null`, only the forest uses it — and `render(ctx, color)`, in logical field coordinates); `init()` also paints their offscreen canvases (`vfxOffscreen`), never per frame; `setActiveBg()` and `resizeCanvas()` (during a match, via `refreshBackground()`) call it, and it draws from `vfxRandom()`.

**Rockola** (`SHOP_CATALOG.music`): music costs no coins and has no `vfx/` renderer; each id is a `MUSIC_TRACKS` key with a `rockola` name (plus `color` on the shop item, `bpm` and, where `loopEnd` is `null`, the file's `duration` on the track), except `random`. Synthwave (default), Chiptune, Funk and Clásica (`musica_gameplay`, the v1 music) are free; Rap Hachepe (`hachepe_rap`) is an exclusive of `beat_hachepe`; «Aleatoria» (`SHOP_RANDOM_MUSIC`) picks one owned track per match. Opening the tab adds the free ones to `owned` (`claimFreeMusic`); «Aleatoria» stays out of every counter (`shopCounts`), so the line reads «Rockola · 4 de 5». Its cards show the loop length and BPM (`shopMusicMeta`) instead of the rarity, keep catalogue order (the sort select hides) and never mount the preview canvas: tapping one plays it in place of `musica_tienda` (`toggleShopListen`, `shopListenId`, a 3-bar CSS equaliser and a «■» `stopShopListen` button); stopping, changing tab or leaving the shop (`endShopListen` in `showScreen`) forgets it with `musicStop()`, so a match starts it from the intro. At ≥1200 px the side panel shows the disc and ESCUCHAR/PARAR (`renderRockolaPreview`). Equipping another track unlocks `rockola_dj`.

### Other subsystems

- `systems/input.js` — `keysDown` Set (anti-ghosting for 2 players); remappable bindings via `isActionPressed(action)`.
- `systems/pointer.js` — touch and mouse write the same `touchY`/`touchX` channel, which overrides the keyboard when non-null. Local mode splits the screen (left half p1, right half p2). The mouse must pick the axis from `bossIsRotatedArena()` — otherwise it does nothing in the Creator's rotated arena.
- `systems/audio.js` — sound effects and the mixing graph. The `AudioContext` is created lazily (the first sound or interaction) together with the graph: effect voices → `sfxBus` (gain = effects volume) and Web Audio music → `musicBus` (gain = music volume, −8 dB while paused), both into `masterComp` (compressor, −14 dB) → destination. Two primitives scheduled on the audio clock (`ctx.currentTime + when`, never `setTimeout`): `sfxVoice()` (oscillator → exponential envelope → optional lowpass → stereo panner when available) and `sfxNoise()` (one shared 1 s noise buffer through a bandpass). `sfxNoise({ kind })` can use a `'lowpass'` instead of the bandpass (boom, stamp, koHit). The prologue added `sfxSustain()` (a held tone with attack/release and optional vibrato), `sfxNoiseLoop()` (looped white or pink noise through a filter; returns its stop function) and a 2 s pink-noise buffer built with `sfxRandom()`; its effects (`crtOn`, `titleChord`, the `cityAmbience`/`rain` loops, `cardHit({ color, major })` whose chord root comes from the Hachepe's hue, … and the rework's `boom`, `heartbeat`, `paddleBreak`, `radioJingle`, `powerDown`) follow the recipes in the prologue guides; the fights by phases add `turnstile`, `bip`, `stamp`, `clang`, `elevatorDing`, `alarm`, `phaseUp` and `koHit` (rework guide, R.7), floors 1–3 add `cashCounter`, `phoneHangUp`, `arcadeBlips`, `lightsOn`, `cellBreak`, `cellRefill`, `coin`, `click`, `buzz`, `cashRain`, `bumper`, `jackpot` and `switchClick` (pisos-1-3 guide, D.7; random notes with `sfxRandom`), and the ending adds `slowClap`, `glassClink`, `auraCrack`, `auraBreak`, `timeStop`, `coffinCharge`, `codeDelete`, `voiceOn`, `goldenPaddle`, `creatorReveal`, `logoCrash` and `yisusSings` (final guide, F.8). The smash charge is the one held voice: `smashCharge(on, side)` keeps one per player in `smashChargeVoices { p1, p2 }` (both can charge in local), panned −0.4/+0.4, all through `sfxBus`. Recipe, with `T = MECH.smashChargeMs`: rising «air» (the shared noise, looped, through a Q 1.5 bandpass going 500 → 2 200 Hz and 0 → 0.05 over T), a rising tone (triangle 196 → 392 Hz over T, lowpass 1 100 Hz, 0 → 0.045 in 0.12 s, 35 % tremolo from an LFO going 5 → 12 Hz), and at T a glassy click (two sines, 1 568 and 2 349 Hz, gain 0.07) while air and tone drop in 0.25 s to a 0.012 whisper with the tremolo at 3 Hz. `smashCharge(false, side)` fades 50 ms and stops every source of that voice, the click included, and the voice goes back to `null`. While a voice charges with music playing, `musicDuckWhile(MUSIC_DYNAMIC.smashChargeDb)` dips the music 2 dB and its release brings it back in 0.3 s. The released smash still sounds `superHit`. `soundEffects` builds every effect from them; hits take `{ x, speedRatio }` for pan and pitch. Their variation (detune, noise samples) comes from **`sfxRandom()`**, never `Math.random` (physics) or `vfxRandom` (cosmetics). With effects off or at volume 0 no voice is created. The file also keeps the old music entry points (`playMenuMusic`, `playGameplayMusic(mode)`, `stopGameplayMusic`, `stopAllMusic`, `pauseAllMusic`, `setMusicVolume`, `setMusicEnabled`) as wrappers of the player. Music and SFX have toggles both in Settings and in the pause menu; both call `toggleMusic`/`toggleSfx`, and `syncAudioToggles()` (`ui/settings-panel.js`) keeps the four checkboxes equal.
- `systems/music.js` — the music player over `MUSIC_TRACKS` (`data/music.js`: file, `loop`, `loopStart`, `loopEnd` — `null` = end of file — copied from `design/actualizacion-v2/musica/bucles.json` and, for the four `prologo_*` tracks, `design/campana/prologo/musica/bucles.json`; the intro plays once, then `[loopStart, loopEnd]` repeats). `musicPlay(id)` crossfades and does nothing if that track already plays; each track keeps its position, so returning to it resumes. `musicPlay(id, { from })` first sets the channel's saved position to `from` seconds (`musicSeek`, stopping it if it was playing; also the `<audio>` `currentTime`), so the prologue starts `prologo_determinacion` at 106 s. `musicStop()` fades and forgets it; `musicPause()`/`musicResume()` back the music toggle (with music off, `musicPlay` only records the track, and the toggle resumes it); `musicPlayOneShot()` plays the jingles; `musicSetRate()` serves the fake ending; `musicSetDuck()` is the pause. **Two engines, chosen per track:** A, Web Audio (only on `http:`/`https:` with `fetch` and `decodeAudioData`): sample-exact `loopStart`/`loopEnd` on an `AudioBufferSourceNode`, falling back to B if loading fails; B, one `<audio>` per track (on `file://` and as fallback): a 25 ms watcher jumps from `loopEnd` to `loopStart`, fades step every 50 ms.   **Dynamic music** (`settings.dynamicMusic`, on by default, «Música dinámica» in Configuración › Audio): one more gain on the looping tracks only (jingles are untouched), `boost × min(hold, timed ducks)` — the strongest dip wins. `musicDuck(db, holdMs, { attack = 0.08, release = 0.4 })` is a timed dip, `musicDuckHold(db)` an untimed one (0 removes it), `musicDuckWhile(db)` an untimed dip that returns its own release function (the smash charge), `musicSetBoost(db)` a rise, `musicDuckReset()` clears all at once (`resetMatchMusic()` in `startGame()`/`quitGame()`, and turning the setting off). Engine A puts a `GainNode` (`musicDynNode`) between each looping track and `musicBus`, ramped on the audio clock; engine B multiplies each `<audio>` `volume` by `musicDynLevel` in 50 ms steps (so the +2 dB rise is capped at `volume` 1). The settings volume and the pause's −8 dB stay separate and multiply. The numbers live in `MUSIC_DYNAMIC` (`data/music.js`). Four reactions: **goal** in every mode, −6 dB for 0.6 s (`goalMusic()`, next to every `endFever()` in `checkGoal` and `practiceMiss`); **smash** (`'super'` hit), −4 dB for 0.3 s (`resolveHit`); **match point** in VS CPU and local only (`tickMatchPointMusic` in `game/match.js`, called from `update()` while the ball is in play): when either side is one point from `matchTargetScore()`, −3 dB and `soundEffects.matchPointBeat()` (two 55 Hz sines of ~90 ms, 0.18 s apart) every 0.9 s (`heartbeat` is the prologue's 4 s faint); the goal removes both and the next serve brings them back if it is still match point; **fever** at 40 hits, +2 dB (removed in `endFever()`). With the setting off there is no dip and no heartbeat, but the fever still switches track. None of it touches `Math.random`.

- `game/powerups.js` — one orb on the field and up to `POWERUP_MAX_ACTIVE` (2) effects in `activeEffects` (`PowerupEffect`: `type`, `beneficiary`, `target`, `remainingMs`, `originalValues`, `data`); the orb only spawns while there is room. Each shield keeps its wall in `effect.data.wall`. **Congelar** targets the rival paddle for 1.5 s: `holdFrozenPaddles()` (`physics.js`, right after `clampPaddles`) puts it back where it was and zeroes its speed, so keys, finger and CPU can't move it and the ball bounces off it as a block; a frozen CPU skips `moveCpu`. After thawing the paddle is immune for `FREEZE_IMMUNE_MS` (`freezeImmuneMs`); a Congelar on a frozen or immune paddle is spent with no effect. The ice is `drawFrozenPaddle`, drawn by `renderPowerupPaddles()` after the paddles. **Rayo** sets `paddle.boltReady` (a mechanics field, reset by `resetPaddleMechanics()`): `classifyHit` makes that paddle's next hit a `'super'` before anything else, and `resolveHit` spends the bolt (`useBolt`, which removes the effect silently) instead of the energy, so a full bar stays full; 20 s without hitting expire it. `drawRayoCharge` glows on the paddle and its pill reads «Siguiente golpe: súper» instead of a bar. **Muro** covers half of the picker's own goal for 8 s with a 12 px wall behind the paddle (`effect.data.goalWall`), the half opposite to the paddle's centre when picked, fixed. `bounceGoalWalls(b)` (`physics.js`) runs in `updateBalls` right before `checkGoal` — not in the shield step after the balls, which would be too late at the goal line — and reflects a ball heading for that goal whose centre is at the wall's height (`wallBlock`). Shields only stop balls heading for their goal and ignore the half a same-owner wall covers (`goalWallCovers`), so the wall bounces first and spends no blocks. `drawGoalWall` flashes in its last 20 %. **Portales** (10 s, one pair for both players) are placed with `Math.random` when they activate (`effect.data.portals`: entrance in the top half, exit in the bottom half, 35–65 % of the width, ≤ 80 px apart). `warpThroughPortals(b, dt)` (`physics.js`, after `bossCollide`) moves a ball whose centre enters either portal to the other one with the same velocity, cuts its trail and plays `portalWarp`; `b.warpMs` (ms since the last crossing, `Infinity` before any) locks both portals for `PORTAL_LOCK_MS`. The CPU's prediction ignores portals: after a crossing in the current approach it keeps the pre-crossing target (`cpuLastPredY`), for `CPU_PORTAL_RECALC_MS` in Imposible and Hachepe and for the rest of the approach otherwise. `drawPortals` sits under the balls. The shield has `SHIELD_HP` (5) blocks instead of a time (30 s only as a safety cap): each block plays `shieldCrack`, the last one reverts it, `drawShieldWallV2` shows the wear (holes are clipped from the wall, never `destination-out`, which would erase the field) and the pill reads "3/5". Waits between power-ups come from `nextPowerupCooldown()` (6–12 s). The field shows an orb with the type's `icon` glyph and `color` (`data/powerups.js` has no emoji); the same glyph and colour feed the pill. The orb, the pick-up burst and the effect overlays (shield wall, big-ball aura, slow-motion vignette, speed lines) are drawn at the end of that file and draw from `vfxRandom()`. The active effects are DOM pills, not canvas: `updatePowerupPills()` (called from `render()`) builds one `.powerup-pill` per effect inside `#powerup-pills-p1`/`-p2`, the beneficiary's side (stacked over the field corner in the `top` and `sides` layouts, side by side in the `stack` pill row, where `#game-container[data-pills]` lets a lone pill take the whole row and compacts two on a phone), and rebuilds them only when the set of effects changes; the score, its pips, the time and the rally are the DOM HUD too (`game/hud.js`), so the canvas draws no score: only the net, or the hearts in the rotated arena. Effects resize paddles, so `startGame`/`quitGame`/`checkWin` restore paddle sizes defensively. `startGame()` restores `width`, `height` **and** `x` (the rotated arena reshapes `p1`).
- `systems/stats.js` also keeps two per-match counters for the HUD and the game-over screen: `matchElapsedMs` (ticked in `update()` only while the ball is in play — not during dialogue, pause or the serve countdown — in real time, ignoring slow-motion) and `matchBestRally`. Both reset in `statsOnGameStart()` and live outside `state`: they never affect play. The same file counts the per-match mechanics (`matchPerfect`, `matchSpin`, `matchSmashGoals`, `matchSmashUsed`, `matchFeverCount`, `matchFeverPoints`). `#game-over-screen` gets `data-result="win|loss"` (local is always `win`) and `data-winner`, which drive its colours, and `body.has-result` (`syncResultClass()` in `game/match.js`) moves the achievement toast to a corner while the pause or game-over screen is up, so it never covers the title.
- `game/hints.js` — first-time hints: `showHint(key)` (`spin`, `perfect`, `fever`, `pu_<id>` with the power-up's `hint` text) shows `#hint-toast` above the field for 3 s, queued, once ever per key (`settings.seenHints`), unless `settings.showHints` is off. The full-energy `#super-hint` uses the same gate under the key `energy`, but shows the first 3 times (`ENERGY_HINT_TIMES`). Hints only touch the DOM and the settings: no `Math.random`, so they never change a match.
- `data/levels.js` + `systems/progression.js` — 50 levels in 10 ranks of 5 (`RANKS`, `levelInfo(n)` → «Aprendiz III», `xpForLevel`, `levelForXP`; level 50 = 34 300 XP). The level is derived from `totalXP`; `checkLevelUp()` pays **every** level between `rewardedLevel + 1` and the new one (`levelReward(n)`: `20 + 5n` coins, a chest of `60 + 6n` on multiples of 5, a new rank on 6, 11… 46, the exclusive `paddles:gold` on 50 via `grantExclusive`) and one prestige star + 250 coins per 2 000 XP above level 50 (`getXPProgress()` then measures the next star). `rankEmblemSVG()` (`ui/progress-ui.js`) draws the rank emblem used by the menu badge (`#menu-level-num`), the game-over screen and the level-up / «¡NUEVO RANGO!» notice. The same file renders «Progreso» (`#progress-menu`, `renderProgressScreen()`): rank card, the 10 ranks, the reward path (levels −2…+3), the missions with a 1 s countdown that stops when the screen is left, and the prestige card (desktop only). In the main menu `#main-progression` holds two buttons: the level block opens Progreso, the coins open the shop.
- Match rewards: `awardGameRewards()` (tables `XP_REWARDS`/`COIN_REWARDS` in `data/levels.js`) builds `sessionBreakdown`, one `{ label, xp }` row per concept (result, points with fever points doubled, perfect hits capped at 10 XP, best rally, smash goals at 5 XP each, perfect game), from the per-match counters of `systems/stats.js`. The game-over screen (`renderGameOverRewards()`, `ui/progress-display.js`) shows it as is in `#game-over-xp-list`, plus a «Misión: …» row per mission completed in the match, the total and the coins, the level card (emblem, a two-segment bar — XP before the match in the theme colour, XP gained in yellow — and the next level's reward) and one card per completed mission; on desktop all of it sits in `.go-col--side`. Practice never gets there.
- `systems/missions.js` — 3 daily missions and 1 weekly (`data/missions.js`), stored in `playerProgression.missions` (`{ day, daily: [{ id, progress, done }], week, weekly }`). They are picked from the local date (`'AAAA-MM-DD'`) and the ISO week (`'AAAA-Www'`) through FNV-1a + mulberry32 — **never `Math.random`**, `vfxRandom` or `sfxRandom` — and renewed by `refreshMissions()` on load and in `startGame()`. `missionEvent(type, amount, info)` is called next to the stats (`systems/stats.js` hooks, plus the power-up pick-up in `game/powerups.js`); practice never counts and win events only come from VS CPU, Hachepe and campaign. Smash events: `smash_use` (every smash of player 1, `statsOnHitType`) and `smash_goal` (`statsOnScore`); `d_win_smash` tests `info.smashUsed`. A stored mission whose id no longer exists makes `refreshMissions()` pick that day's (or week's) missions again. Completing one pays at once, plays `missionComplete`, queues a toast in the achievement toast queue («Misión completada») and is listed in `sessionMissions` for the game-over screen. The same local date always gives the same picks (so they depend on the machine's time zone).
- `systems/achievements.js` — `unlockAchievement(id)` is idempotent and queues toasts; it does nothing visible for an id missing from `data/achievements.js`. `secret: true` entries show as `????` and are excluded from `getVisibleAchievementsTotal()`. Each catalogue entry has a `category` (its colour in `ACHIEVEMENT_CATEGORIES`) and an `icon` (the `d` of a 24×24 stroke glyph); `achievementMedalSVG()` (`ui/stats-panel.js`) draws the hexagonal medal for the list and the toast. Cumulative achievements read their threshold from `ACHIEVEMENT_GOALS`, which both the unlock checks (`achievementGoalMet`) and the progress bars (`getAchievementProgress`) use — change a target there, never as a literal. Level and prestige achievements are checked in `checkLevelUp()` (`checkLevelAchievements`), mission ones when a mission completes (`checkMissionAchievements`), and both again at the end of a match. `portal_goal` unlocks when player 1 scores less than `PORTAL_GOAL_MS` after the ball crossed a portal (`checkGoal`; `exclusive_first` comes from `grantExclusive`, `buy_legendary` from `buyShopItem`, `rockola_dj` from `equipShopItem`). The secrets (`the_creator`, `nadie_sabe_tu_nombre`) are drawn at the end of the Campaña group and, while locked, show the "?" glyph in grey: never their icon, name or colour.

## Repo notes

- `css/style.css` is one file split by banner comments; Tailwind utilities carry most of the layout, `style.css` the retro/CRT identity and the custom properties (`--primary`, `--primary-rgb`) that `systems/theme.js` rewrites per theme. Canvas drawing reads the same colour via `currentThemeHex()`.
- The UI redesign ("gabinete arcade de neón") is being implemented in phases from `design/rediseno-ui/README.md` (untracked, owned by the user). Its design tokens (`--bg`, `--surface`, `--text`, `--muted`, `--gold`, `--danger`, `--p2`, `--on-primary`…) live in `:root`; derive theme colours with `rgba(var(--primary-rgb), a)`, not hard-coded hex. Reusable pieces sit under the "Sistema visual" banner: `.btn`/`.btn-p`/`.btn--danger`, `.icon-btn`, `.panel` + `.brk` (HUD corners), `.tile`, `.chip`, `.xp-track` (segmented by a mask, no JS), `.floor` (synthwave grid, placed inside a `.screen`), `.px`/`.lbl`/`.ico`. The older class names `.key-btn` and `.option-pill` are kept and already share that look. Toggles are `.tgl` styled on the `<input type="checkbox">` itself (`appearance: none`), and the percentage rings are `.pct-ring` with the value in `--pct` — not `.ring`, which is a Tailwind utility.
- The in-game HUD lives in the DOM, outside the field: `#game-container` is a CSS grid whose direct children are `#hud-mode`, `#hud-p1`/`#hud-p2` (cards with name, score, one pip per point and the 10-segment energy bar `#hud-energy-*`; full, the card gets `.is-super`), `#hud-stats` (time and rally; `#hud-rally-chip.is-fever` during a fever), `#mobile-pause-btn`, `#smash-btn-p1`/`-p2` (touch only), `#canvas-wrapper` (with `#super-hint` inside), `#powerup-pills-p1`/`-p2` and `#orientation-hint`. `setupHud()` (`game/hud.js`) fills it in `startGame()`; `updateHud()`, called from `render()`, only writes when the score, rally, second, fever or lit energy segments change. The top cards have a fixed height, so the energy bar does not move the canvas. `resizeCanvas()` measures the field cell with `data-measuring` set (the field track takes all the free space), then sets the canvas and wrapper size and `--field-w`/`--field-h`, which size the tracks so the HUD hugs the field. The container must not get `position: fixed` or a `z-index`: that would create a stacking context and hide the campaign `#dialogue-box` (z-index 50) under the game-over screen, where the boss's farewell line is meant to show.
- Any keyframe animating `transform` on a centred element must re-apply its `translateX(-50%)`, or the element jumps out of the viewport — that is why `#dialogue-box` has its own `dialogue-shake`.
- `.mcp.json` configures the Playwright MCP server (`--browser msedge`, since Chrome isn't installed on this machine). It wraps `npx` in `cmd /c` because npx is a `.cmd` on Windows — change that to plain `npx` on Linux or macOS.
- Responsive rules: safe areas are `max(<old padding>, env(safe-area-inset-*))`, which resolves to the same pixels without a notch; 44px touch targets live in the `@media (pointer: coarse)` block at the end of `style.css`.
- Playwright output (`.playwright-mcp/`) and stray root-level `*.png` are gitignored. Keep captures out of the repo.
- `docs/bugs-conocidos.md` records the bugs found during the 2026 refactor and how each was later fixed. A refactor must not change behaviour; a bug fix is a behaviour change: do it in its own commit and say why in it. If a bug must be kept for now, mark it in code with `BUG conocido (conservado)` and list it in that file.

## Verifying changes

There is no regression suite any more (it was removed in commit L.1). Claude Code checks every change itself in a real browser through **Playwright MCP** (`.mcp.json`, Edge); the full procedure is `design/actualizacion-v2/verificacion-playwright.md`. Playwright is a development tool only: no `package.json`, `node_modules/` or Playwright config in the repo. Run the server in the background with `python tools/serve.py` (port 8000), e.g. `Start-Process python -ArgumentList 'tools/serve.py' -WindowStyle Hidden`.

### Level 1 · every commit (1–2 minutes)

1. **Types:** `npx -y -p typescript@5 tsc -p jsconfig.json` must report **zero** errors (JSDoc `@typedef`s for `Ball`, `Paddle`, `GameState`, `BossMechanics`, `PowerupType`, `ShopItem`… live next to the code they describe).
2. **Load:** open `http://127.0.0.1:8000/` with Playwright: no console errors, no 404 in the network requests.
3. **If the commit adds, moves or deletes a file of `js/`:** check the script list in `index.html` by hand (see «Cache-busting»).
4. **Version:** bump `?v=N` everywhere if any JS or CSS changed.

No screenshots and no simulated matches at this level.

### Level 2 · once, at the end of a phase (10–20 minutes)

In a clean Playwright context (`localStorage.clear()` and reload first):

1. **Both protocols:** `http://127.0.0.1:8000/` and `file:///…/index.html`, no console errors in either. On `file://` music goes through the `<audio>` engine: check it plays, or that `musicCurrent()` returns the expected track.
2. **Screens the phase touched,** captured at **390×844, 844×390, 768×1024 and 1280×800** (`browser_resize`). Look at every capture: cut text, buttons that overflow, overlaps, contrast. At every size, `document.documentElement.scrollWidth <= innerWidth` (no horizontal scroll).
3. **Simulated matches** with `browser_evaluate`, calling `update()` in a loop, with three bots: **perfect** (hits with the edge so rallies end), **medium** (±30 px error) and **bad** (misses one in three). In all three the match ends, `checkWin` is reached, there is no `NaN` in balls or paddles, and no ball goes more than 600 frames without crossing the centre.
4. **Determinism** (what the old `match` golden protected): seed `Math.random`, play the same match twice changing **only** cosmetics, and the trajectory must be identical. Call `render()` so the effects run:

   ```js
   function seeded(seed) { return () => { seed |= 0; seed = seed + 0x6D2B79F5 | 0; let t = Math.imul(seed ^ seed >>> 15, 1 | seed); t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t; return ((t ^ t >>> 14) >>> 0) / 4294967296; }; }
   function runTrace(equip) {
       Object.assign(playerProgression.equipped, equip);
       const real = Math.random; Math.random = seeded(1234);
       startGame('cpu'); stopLoop();
       let trace = '';
       for (let i = 0; i < 6000 && state.isPlaying; i++) {
           state.serveCountdownMs = 0;
           const t = state.balls[0];   // p1 follows the ball without Math.random, so there are rallies
           if (t) p1.touchY = Math.max(0, Math.min(GAME_HEIGHT - p1.height, t.y - p1.height / 2 + 22));
           update(1); render();
           const b = state.balls[0]; if (b) trace += b.x.toFixed(3) + ',' + b.y.toFixed(3) + ';';
       }
       Math.random = real;
       if (state.isPlaying) quitGame();
       return trace.length + ':' + [...trace].reduce((h, c) => (h * 31 + c.charCodeAt(0)) | 0, 0);
   }
   const a = runTrace({ trails: 'default', paddles: 'classic', backgrounds: 'none', goalEffects: 'classic' });
   const b = runTrace({ trails: 'rainbow', paddles: 'pixel', backgrounds: 'aurora', goalEffects: 'confetti' });
   [a, b, a === b];
   ```

   If `a !== b`, a visual or sound effect is using `Math.random`: find it before going on. Add the categories a phase introduces to both sets. Stop at the end of the match: `update()` does not check `state.isPlaying` (the loop does), so calling it after the final goal keeps scoring and runs the whole `checkWin()` again on every goal, which takes minutes.
5. **The phase's own checks** («Verificación con Playwright» / «Comprobación a mano» in its guide).
6. **Report** to the owner: what was checked, which captures were looked at, what failed and how it was fixed, and what is left for the manual check (above all sound and feel on a real phone).

While anything fails the phase isn't done: fix it in its own commit and repeat only the step that failed.

Everything is global, so Playwright MCP's `browser_evaluate` can drive the real game directly:

```js
prepareCampaignMatch(4); startGame('campaign'); stopDialogue();   // the VS timer restarts it ~3 s later
for (let i = 0; i < 3000; i++) { state.serveCountdownMs = 0; update(1); }
```

Two habits worth keeping, because both caught real bugs that reading the code did not:

- **Simulate several player skill levels**, not one. A perfect bot rallying forever against a perfect CPU is how the unbeatable-boss and stuck-ball bugs stayed hidden; the test bots use edge hits for that reason.
- **Look at the screenshots.** The giant square paddle, the dialogue box sliding off screen and the armor stripes bleeding over the eye were all invisible in the numbers.
